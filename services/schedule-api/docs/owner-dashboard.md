# Local owner dashboard

The hosted dashboard is live at **https://bye-admin.jack-truong2k1.workers.dev**.
See [Cloudflare operations](hosted-owner-dashboard.md). The local workflow below
remains available as an optional development tool; its server is currently stopped.

The dashboard is local only: http://127.0.0.1:4178. It binds exclusively to IPv4
loopback and requires Node 24.3+. Start it from `services/schedule-api/`:

```powershell
npm ci
# .env contains only public Auth configuration for dashboard use:
# BYE_SUPABASE_URL=https://nahvhampsxtasfwvvfei.supabase.co
# BYE_PUBLISHABLE_KEY=<genuine Supabase publishable key>
npm run admin
```

The local ignored `.env` has been prepared on the owner's machine. No database,
service-role or cron credential is required to run this dashboard. An optional
`BYE_OWNER_EMAIL` restricts email-code requests to that address.

Sign in with the existing BYE account approved as owner. Enter the code directly
in the dashboard, never in chat. The existing Auth email template must include
its code; no Auth settings or review email templates were changed in this phase.
Unknown/non-owner accounts cannot grant themselves permission.

## Bootstrap and recovery

Use a private owner shell with the existing machine credential, not the browser.
Approve only a verified, non-deleted Supabase Authentication user UUID:

```powershell
$env:BYE_JOB_TOKEN = '<existing private machine credential>'
npm run owner -- owner-add <user-uuid>
# Optional alternative: BYE_SERVER_KEY instead of BYE_JOB_TOKEN.
```

To recover access, approve another confirmed account through that same private
command. `owner-remove <uuid>` removes an owner but refuses to remove the last.
The owner allowlist is bounded at 20 accounts. Initial approval for the UUID
provided in this conversation was completed through the private database gateway.
Keep administrative credentials out of `.env` used to start the local dashboard.

## Sessions and local protections

Supabase access tokens stay in server memory. Refresh tokens are discarded.
Browser storage and disk never receive Auth tokens. The browser receives a random
HttpOnly, SameSite=Strict session cookie and an in-memory CSRF token. Sessions
expire with the access lifetime or after one hour, whichever comes first. Restart,
sign-out and expiry clear local sessions; sign-out also attempts server-side logout.

All mutations require the exact loopback Host and Origin, JSON, a custom header,
and (after login) CSRF. Asset responses have a restrictive CSP. The server permits
8 active operations, 8 sessions and 16 connections, bounds bodies to 8 KiB, and
uses timeouts. Email sends are limited to 3 per ten minutes; verification attempts
to 20. Supabase's own Auth limits also apply. The dashboard is not remotely hosted.

## Management API

`POST https://nahvhampsxtasfwvvfei.supabase.co/functions/v1/bye-key-admin`

Supply the genuine Supabase publishable `apikey` and `Authorization: Bearer <owner
access JWT>`. Every request validates the user with Supabase Auth and invokes
`public.bye_key_management` with that same user JWT. Database operations check
`auth.uid()` against the private owner allowlist. A public schedule key alone
cannot authorize this endpoint. The local server proxies it without exposing JWTs.

JSON body: `{ "action": "list", "args": { "offset": 0 } }`.
Actions: `session`, `list`, `audit`, `create`, `rotate`, `extend`, `disable`,
`enable`, `revoke`. Lists use 25-record pages. Mutation arguments:

- Every mutation: `requestId` UUID and `requestedAt` ISO timestamp.
- Create: `label` (1–80 characters), `clientType` (`windows`, `mac`, `website`, `other`).
- Rotate: `id`, current `revision`, label and clientType for the replacement.
- Extend: id/revision, optional `retireAt`, `confirmRestore: true` if expired.
- Disable/enable: id/revision. Revoke: id/revision and `confirm: true`.

IDs, random plaintext and digests are generated by the management service, not
accepted from the dashboard. Successful create/rotate returns `key`, optional
`previous`, `replayed`, and one-time `plaintext`. No list or audit returns secrets.
A replay returns original metadata and `keyRecoverable: false` without plaintext.

Errors use `{error:{code,message,retryable}}`. 401 is invalid/expired login, 403 is
non-owner, 409 is revision/idempotency conflict, revoked key or registry capacity;
429 includes Retry-After: 60; 503 indicates an unavailable dependency. Invalid
arguments or expired retry windows return 400. Owner DB calls are bounded to 240
per minute, shared across dashboard sessions; the Edge handler checks owner access
before invoking the requested operation, so one action usually consumes two calls.

Idempotency receipts last 24 hours and are capped at 2,500; full receipt storage
rejects new mutations rather than evicting valid receipts. `requestedAt` prevents a
retry after receipt expiry from silently creating a new key. The dashboard keeps
an uncertain operation in memory and offers Retry uncertain request with the same
request ID. If the page is closed or the retry window expires, inspect keys/audit;
revoke an unrecoverable key before deliberately creating another. Do not blindly
repeat Create. Revision checks reject stale edits and competing rotations.

## Deployment and rollback

The additive registry migration is in `supabase/migrations/20261018044753_client_key_registry.sql`.
Its legacy digest was verified against the deployed v4 read function before use.
For another project, explicitly verify and adapt that compatibility seed first.
Apply the migration once, deploy the three independent functions using `npm run
deploy`, then approve the owner. Preserve `BYE_JOB_TOKEN_SHA256` for the worker.
The deploy tool injects the public Supabase Auth key, not schedule key digests.

For a compromised BYE key, revoke it and create/rotate through the dashboard. For
management-service trouble, stop the local server and redeploy a tested
registry-compatible version. Keep private tables and owner records. Do not roll
back to the old compiled-key read handler: it could bypass revocations. Schedule
snapshot rollback remains the existing owner command, separate from key management.
Never revoke Supabase project credentials to revoke only a BYE client key.
