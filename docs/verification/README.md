# Verification records

## What these records establish

This folder preserves dated Markdown reports and JSON evidence from platform, integration and AI experiments. Keeping the original records makes decisions auditable without implying an old result verifies today's source or a deployed release.

## How to use them

- Start with [Project status](../project/PROJECT_STATUS.md) and the [testing guide](../project/testing.md) for relevant platform checks.
- See [Windows integration](../windows/WINDOWS_API_INTEGRATION.md) for its recorded acceptance and limitations.
- See [schedule service verification](../../services/schedule-api/docs/verification.md) for backend evidence.
- Browse the dated files in this folder for historical details; their timestamps and tested configurations define their scope.

Desktop owns these records. New behavior needs fresh checks; documentation relocation does not revalidate apps, infrastructure or AI models. Preserve raw evidence filenames and distinguish offline fixture checks from live acceptance.
